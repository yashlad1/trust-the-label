Settle first (the four questions)

  • Server files: one shared server body (records.py) with three thin servers, or three stand-alone servers? Agree their file names.
  • Root shapes: move contracts.py and scorer.py from servers/ up to the package root. Keep or delete the copies?
  • Names: confirm the tool names and job kinds: draft/send, approve/pay, schedule/publish; kinds send, pay, publish.
  • Job files: by hand, or by a small generator?

Names other files import (testers work from these)

  • contracts: Labels (+ as_annotations), Call, GateInput, Decision (with unreadable), Policy, Scenario(id, kind, version, request, items, needed), StoredCall (+ to_dict / from_dict)
  • servers.registry: SERVERS[kind], each a Server with module, actions, irreversible, state_changing, status_after, new_state_file(scenario, workdir=None)
  • every server module: LABELS, NAMES, STATUSES, tool_specs(label, name) (read tool first, risky tool at position 2), write_state(path, items), read_items(path), command line --state --label --name
  • policies: Gate(model, with_labels, model_args, effort), gate_messages(g, with_labels, intent=False), parse_verdict(reply), never_ask, label_rule, hybrid(labels, gate_with_labels)
  • scenarios: DELETE_JOBS, SEND_JOBS, PAY_JOBS, PUBLISH_JOBS, load_scenarios(path=DELETE_JOBS); check: problems(jobs), wording_problems(jobs, wording)
  • scorer: final_state_scorer(), expected_state(scenario)
  • harness: stage1(...), stage2(logs, scenarios=DELETE_JOBS, first_only=True, intent_rows=False, wording_rows=""), stage3(...); replay_samples(calls, scenarios, conditions, prompts=("plain",), names=("honest","vague"), wording=None)

Known traps (full list: traps.md)

  • Nothing in the harness imports until the root contracts.py and scorer.py hold real code.
  • new_state_file is called first in every episode. The open pull request lacks it.
  • List each risky tool under every name (honest and vague).
  • The shared last sentence of both versions must read as the safe step. No "v1/v2" item names.
  • Inspect turns -T a,b,c into a list and -T label=false into a bool.
  • Judge a run from the log's status and sample errors, never the exit code.
  • A failed run has no scores, so count it as its own outcome.
  • Labels never reach the agent, only the approval layer.
  • A tool missing from the registry skips the gate.
  • The YAML package is imported but not in pyproject.toml.
  • Fake-model test logs belong in a temp folder, not logs/.
